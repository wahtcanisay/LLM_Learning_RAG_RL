2026-09-23 证据协议同步：检索数据不强制 ID，Evidence 仅含 text、可选 title 和 score；不补哈希 ID、不按 ID/标题去重。原文与实际可见片段随结果传给 SearchAgent/Verifier/Generator，具体关联和引用形式待接线时讨论；任务归属用独立随机 run_id，不能用检索文档标识承担隔离。评测题 ID、记忆条目 ID、快照身份和数据去重清单保留，它们不要求为在线检索结果设 ID。

## 前置工程与V1实验（先于记忆实验）

E0：学生实现RoleRunner并完成planner/verifier真实messages隔离；补401/暂态/挂起请求次数与有界退出检查。SDK源码构建固定UPSTREAM.lock，不依赖未验证PyPI包；默认只用假服务。
E1：完整 V1 前补齐真实分支需要的契约、安全输入、总额度和 trace 接线，验三路由、一次返工、弃答和失败；这些是工程验收，不是医学效果。当前 P3 可先做局部 Evidence/BM25 接线，不要求先编码完整状态表或通用预算框架。
E2：提醒费用后做一次短真实DSH角色调用，验实际usage；冻结可用3B服务/模板/标签与BM25端点。原训练AgentLoop不能直接视为部署HTTP服务。
E3：V1 5～10题工程smoke，再进行冻结集合B0/B1/B2/B3。B1固定检索、B2动态无语义返工、B3增加语义验证与一次返工；首版不强制额外 structure 调用，声明映射随同一次语义审查产生，全部实际调用成本计入。B0更换候选模型等差异不作检索单因素归因；B3 无返工可隔离返工作用，当前 workflow 的 max_retries 实际为总尝试数，此时传 1，不能传 0。
E4：V1角色版本、Prompt、服务和预算冻结后才开始以下V2实验。故障注入与医学评分分层报告。不要求程序意外退出恢复，也不把软件测试通过写成医学正确。

## 主张与边界

主张 C1：冻结在线模型和检索器时，离线维护的流程记忆能改善独立问题表现。
主张 C2：相同记忆容量下，质量维护优于简单 LRU；排除提升仅来自存更多、更多推理或泄漏答案。
不预设正确率单调上升；展示所有快照及负向结果。程序意外退出恢复不在范围内。
Qwen 是用户提出的离线维护模型候选，拟用 Qwen3-4B-Instruct-2507，不替换在线 Planner/Verifier/Generator。项目书V2已允许离线第三类LLM例外，V1在线模型保持不变。每题执行期间冻结快照；批次间离线维护属于V2，不自动激活未经审核的总结。

## 数据

既有 RL dev 已用于诊断，进度文件记录扩充后 396 条，当前实际文件数量/hash 尚待核对。可以作为 Harness dev 诊断，不能当未见最终测试。
若转作 memory_build，导出独立用途清单并保留旧 RL dev 原文件；其题目与改写不能再作为独立效果证据，且需冻结 RL checkpoint、避免继续混用其 RL 选模职能。
首轮从核验后的旧 RL dev 固定划出 memory_build 200 题，其余作为内部 memory_eval；按合并清单396条推算余196条，实施时核验而非假定。活跃记忆上限100条，不强制凑满。若做曲线，从剩余题预先取50题probe，独立最终确认使用其余题；一旦据probe调参，不把它合入独立测试。MIRAGE/MedAgentsBench遵循项目书V2.3的外部验证与独立构建两种分开的协议。
不能将已有 MIRAGE 最终保留集拿来反复调参；若需要转换其中部分用途，先明确划出 probe 并保留其余 test，记录用途变化。
核对 SFT/RL train/dev、记忆构建集和所有评测集的源 ID、规范化、词汇及语义重复；公共预训练污染无法靠本地去重排除。

## 框架选择

主线复用 MIRAGE 医学选择题及评分脚本，Harness 外围增加快照循环与故障注入；不能声称这些补充是官方评分器功能。MIRAGE 原协议是 zero-shot、question-only retrieval；记忆增强与可能偏离的检索策略须注明自定义协议，不直接对齐官方榜单。
MedAgentsBench 是难题问答补充，须检查与 MIRAGE 的题目重叠。MedAgentBench 是 EHR/FHIR 操作，MedAgentGym 是代码医学任务，均不直接适配当前只读医学搜索权限。
HealthBench 可选用于开放答案质量补充；其参考实现使用 rubric grader，成本与替换 grader 的偏差需单列，不能替代状态机恢复测试。

## 核心实验

V2-E1：先做 10 道构建题、10 道隔离 probe 的协议 smoke；验证参数固定、无 gold 注入、快照不变、答案评分和故障终止，不作效果结论。
V2-E2：固定同一份完整 Harness 构建轨迹流，按每 10 道完整问题一个批次，得到 S10...S200。这里不是 RL optimizer step 或工具调用次数。首轮生成 200 道完整题的轨迹；旧 RL 轨迹缺少 Planner/Verifier/Generator，仅可调试提炼，不冒充完整 Harness 历史。
V2-E3：比较 M0 无记忆、M1 相同审核候选的定容量 LRU、M2 相同候选与容量的去重/版本过滤/分类保留/LRU。维护M1/M2使用相同记忆表示；不是原B4/B5的向量/图对比。同 encoder/top-k/hops/prompt/在线模型/生成及搜索预算；每个测试 run 独立重置。相同候选让 M1/M2 隔离维护选择效果，不能据此证明 Qwen 提炼胜过规则；若宣称提炼价值另做消融。
每批 Qwen 只读公开动作、证据引用、错误码和必要片段及相关旧记忆，不读隐藏思维链或整个不断增长的库。产生候选与修改建议；程序查 Schema/来源/容量，人工审核首批适用条件和反例。构建集答案标签可供独立 evaluator 产生结果反馈，答对不证明经验正确，金标和题目答案不进入在线经验。
首轮只在S200完成后跑有/无记忆两组的全部内部eval；若可用196题，共392评测题次，补LRU则588题次，另200构建题次。每10题维护但不每批全量评测；可选曲线只在0/50/100/200跑预先固定50题probe。所有数值基于待核验样本量。正式结论按预算增加配对seed，报告构建顺序和生成波动。
V2-E4：协议与阈值确定后冻结最终快照，在独立 final_test 先比较有/无记忆两组，按预算补LRU第三组；预先指定使用最后一个快照，若以 probe 选最佳则记录选模并在独立 test 验证。
V2-E5：软件故障注入用假服务覆盖持续失败、非法动作直接终止、证据不足返工、预算终止，不需 API 成本。首版传输自动重试和动作纠错均为 0；暂态失败后自动恢复仅在未来明确增加该机制时验，不为实验标题提前造恢复框架。知识正确性与故障处理独立报告。

## 指标与图

主图 x=已经处理的构建问题数，y=同一 probe 的 Accuracy，M0 水平参考；不能比较不同批次题目的裸正确率后宣称进步。报告重复运行均值和不确定性，最终差值按同题配对 bootstrap，种子结果单列。
选择题按规范答案 ID 判分，非法/弃答/执行失败在总体准确率记错，另报 coverage；开放答案不能以宽松 token-F1 代替医学正确性，独立人工或经校准 grader 评审。没有证据 qrels 不计算真值 Recall/MRR。
副指标：引用有效率、独立支持性审核、对变错/错变对、unsafe 标签、轨迹完成、搜索次数、重复调用、返工恢复、token/API费用/本地时间、快照大小/条目/淘汰及拒绝数、维护审核成本。对变错只能视为配对负向变化，不自动归因某条记忆。
引用有效率以实际传递的可见证据和后续冻结的引用格式为依据，不再以证据 ID 存在率代替；若 qrels 无法与当前结果可靠对应，不报告 Recall/MRR，也不为凑指标给 Evidence 恢复 ID。
成功条件：独立测试在可接受成本和安全约束下显示可信改善；零差异/下降保留并分析任务不需要记忆、提炼错误、召回失败或评分噪声。小样本无提升不自动扩大调用规模。

## 成本与执行顺序

当前文档更新不下载模型、不发起付费调用。E0～E2 是正式 V1 实验前必须补齐的准入；局部编码顺序以工程书当前 P3-c 起的任务表为准，不倒退到重写已完成项。E3→E4 之后进入 V2，先数据用途清单，再10+10 smoke，预算外推后才扩大。付费凭据接入前提醒用户；现有价格仅为历史2026-09-15快照，实际调用前复核。
本地 Qwen 分阶段加载，避免与 MedSearch/训练同时挤占 32GB 显存；未测量 GPU 小时与峰值，不报估计硬值。公式：总调用成本=各次命中输入、未命中输入、输出 token 乘当时单价，维护和在线分开记。一次题次包含多个角色调用。

以每题全部 API 调用合计假设20000未缓存输入+4000输出：空闲0.036元/题。若196题两组评测加200构建题，共592题次约21.312元；补LRU后788题次约28.368元。仅演算，不是实测或保证；可选曲线/重复seed/重试/思考输出另计，本地维护时间和人工审核成本单列。
