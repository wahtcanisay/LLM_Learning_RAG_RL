## 1. 目标与定位

在单张 RTX 5090 32GB 上，参考 DGPO 的“教师冷启动 + 学生自主探索 + 失败时教师指导”思想，训练轻量医学证据搜索 Agent。

本项目按可复现的求职展示项目收敛范围：目标是在固定的独立测试集上，验证同尺寸学生相对通用基座及相对同起点、同数据、同训练预算的直接 RL 基线是否改进。允许选择适合验证搜索行为的公开题目子集，但筛选规则须在评测前固定，保留完整分母与失败轨迹；不以绝对分数高低作为唯一完成标准，也不把开发集挑选或判分器误判包装成测试提升。展示重点包括 veRL 实际训练链路、合法搜索轨迹、答案指标及成本，而非临床能力声称。

项目采用 DGPO-like 适配，不声称原样复现 DGPO。保留现有 MedSearch 的医学检索、AgentLoop 与训练工程基础；2026-09-19 决策更新：新实验采用 GRPO + 失败门控 OPD，替代此前 DAPO 方案，不从头重写整个 Agent runtime。

## 2. 已确认模型与职责

| 组件 | 选择 | 职责 |
|---|---|---|
| 冻结教师 | Search-R1 Qwen2.5-7B 系列 | 生成冷启动搜索轨迹；提供教师概率监督 |
| 学生 | Qwen2.5-3B-Instruct | 学习搜索策略并进行医学任务 RL |
| 答案判定器 | medical-o1 verifier 3B，延续现有模型 | 比较最终回答与参考答案，用于筛选、奖励与失败判定 |
| 硬件 | 单张 RTX 5090，32GB | 师生资源需按阶段调度 |

教师具体 checkpoint/revision、verifier 实际模型路径与 revision 在执行前核实固定。HuatuoGPT-o1 医学推理模型与 medical-o1 verifier 不是同一个模型；本项目的搜索蒸馏教师始终是 Search-R1 7B。

## 3. 已确认数据来源与划分

直接使用 `FreedomIntelligence/medical-o1-verifiable-problem` 的开放式问题和标准答案。作者从 MedQA-USMLE、MedMCQA 训练题筛选并改写出该题库；本项目不重新把选择题改写一遍，也不将官方推理 SFT 数据直接视为真实检索轨迹。

本地合并记录中的当前规模为 train 3,283、dev 396；正式新版数量须通过文件回读和清洗结果验收。

目标扩充为约 5,000 条 train + 500 条 dev，再将 train 按 2:8 分为冷启动与 RL：

| 集合 | 目标题数 | 用途 |
|---|---:|---|
| 冷启动问题池 | 1,000 | 两档冷启动共用，交给教师生成搜索轨迹 |
| RL 问题池 | 4,000 | 各 RL 对照分支共用 |
| dev | 500 | 开发诊断、选配置与 checkpoint，不参与训练 |
| 最终测试 | 延续已有冻结资产 | 最终效果报告，不参与训练或数据筛选 |

冷启动与 RL 严格不重叠。优先保持现有 3,283 条训练题归 RL、396 条 dev 归 dev；从新增合格题中分配 1,000 条冷启动、717 条 RL、104 条 dev。该安排既满足目标比例，也避免将旧 RL 训练题转入冷启动。

先按问题及近重复组固定归属，再生成教师轨迹。教师失败题不自动转入 RL 或 dev。历史已训练 checkpoint 的数据暴露必须记录，不能用其初始化后宣称阶段数据完全独立；新对照从固定原始学生基座及对应新冷启动产物开始。

2:8 指候选问题池划分。教师生成与过滤后，实际冷启动训练轨迹可能不足 1,000 条，必须报告实际数量，不通过放宽质量规则补齐。

## 5. 已确认的两档冷启动

| 分支 | 目标 | 数据关系 |
|---|---|---|
| A：CE-only | 模仿教师生成的动作与答案 token，序列蒸馏 | 与 B 共用同一份有合法最终答案的轨迹 |
| B：CE + Top-k | 在 CE 上增加教师 Top-k 分布监督 | 仅额外增加教师分布缓存 |

两档分别保存 checkpoint，后续分别做 RL。A/B 的基座、问题、轨迹、数据划分及预算口径保持可比较，避免同时改变数据质量与损失函数。

教师调用搜索时必须使用真实医学检索器，不能自行生成 information 充当证据；0 次搜索也允许。标准答案仅供记录 verifier 判定，不进入教师或学生作答输入。

首版每题一次完整教师尝试，不自动重试。2026-09-29 用户将冷启动筛选改为：只要求教师轨迹有合法、非空的最终 `<answer>` 动作；无最终答案的轨迹不进入训练。verifier 判错、先前出现无效动作或没有检索，不再构成冷启动排除理由。原始 1,000 条 attempts 和旧的严格筛选结果保留作审计；从中派生的训练集为 886 条有答案轨迹，另有 114 条无答案轨迹排除，见 `data/distillation/teacher_cold1000_20260929_answered/manifest.json`。这属于教师行为模仿，不能把训练轨迹称为医学正确答案。

模型生成位置参与学习；system/user、检索 observation 与环境提示只作上下文，不作为生成目标。2026-09-20 用户批准 B 档固定 K=32，不以先比较多个 K 作为启动前置条件；概率质量指标沿用 veRL 已有输出，不新增专门监测。用户进一步批准温度 T=1、冷启动权重 alpha=0.1，目标 L_B=L_CE+0.1*L_TopK；两项使用相同有效生成位置和平均口径，分别监测损失与梯度贡献。0.1 是本项目保守起始值，不是已验证最优值，也不是 DGPO 原始冷启动 lambda=1.0；它与在线 OPD 的 0.001 候选系数独立。Top-k 损失沿用 veRL 现有 forward_kl_topk 实现，不新增 other/tail bucket、尾部处理实验或专门日志，不把尾部处理列为前置工作。Top-k 是对分布蒸馏的近似，不称为完整 forward KL。

2026-09-26 已对候选教师 `PeterJinGo/SearchR1-nq_hotpotqa_train-qwen2.5-7b-it-em-ppo` revision `74d46a43224daa612b5f27174e1c58b35587ee92` 与学生 tokenizer 做逐项核对：151,665 个 token 的 token→ID 映射、BPE、special tokens、chat template 和样例编码一致；A 档可直接复用原始 token ID，结果见 `docs/audits/searchr1_7b_vs_qwen25_3b_tokenizer.md`。2026-09-27 已下载完整 7B 权重并核对七个分片哈希，真实 BF16 模型短动作 sampled 评分通过；实际搜索轨迹与 Top-32 尚未实测，见 `docs/audits/searchr1_7b_teacher_smoke_20260927.md`。最终教师 checkpoint 如变更须重做核对。教师/学生输出层分别有 152,064/151,936 行，实际 tokenizer ID 仅为 0–151,664。B 档 Top-k 和在线 OPD 在概率接线时，应先对两侧未映射输出行作一致屏蔽，再在共同 token 集合上归一化；不能仅截断教师 Top-k ID。batch attention mask 按真实长度构造，不凭配置中的 `pad_token_id=151643` 判别有效位置。当前结果不代表完整单卡切换或蒸馏训练已验收。

## 6. 已确认的搜索预算

- 首版每条轨迹最多 2 次检索工具调用，允许 0、1、2 次，不强制搜满。
- 教师冷启动、学生 RL 和可比较评测使用同一搜索上限。
- 第二次检索返回后仍给予一次最终作答机会；搜索次数不等于模型生成轮数。
- 2026-09-20 用户确定直接采用 Search-R1 的 4096 + 500 长度口径：4096 的上下文预算、单次模型生成最多 500 tokens；不再以 2048 为起点或重复其可行性试验，用户已在此前实验中遇到大量截断。仍保持最多两次搜索，并保留最终作答机会。
- 接线时区分上述长度口径与 veRL 的初始 prompt、整条 response（可能包含 observation）、engine max_model_len 等字段，不将 500 错设为整条多轮轨迹的总生成预算。现有 V9 脚本为 max_prompt_length=512、max_response_length=4096、max_model_len=4608，AgentLoop 默认 max_action_length=500；需显式映射本轮长度配置，不原样假定所有同名字段语义一致。这是配置对齐，不重开 2048/4096 选型。
- 2026-09-26 用户决定沿用 Search-R1/veRL 的长度配置和已有动作截断，不为预算另建 `episode.py`、`EpisodeState` 或 `generation_budget()`。先做现有 loop 的最小协议 smoke；若真实失败，再局部修正。
- 后续可单变量比较增加至 4 次；依据失败原因决定，不能默认更多搜索一定更好。

## 7. RL 与失败 OPD

总体方向：从 A/B 两个冷启动 checkpoint 分别开展 GRPO，并研究失败轨迹 OPD 的额外收益。学生产生真实搜索轨迹，medical-o1 verifier 判定学生最终答案；教师在学生实际访问的上下文上提供概率监督。

已确认分流：全错组的答案相对优势为零，全部失败轨迹进入 OPD；部分答错组按完整原组奖励计算 GRPO 优势，仅失败轨迹进入 OPD；全对组答案优势为零且不做失败 OPD。零方差组需数值保护。若另有 reference KL 或 entropy 项，答案优势为零不代表总梯度必然为零。

关闭 DAPO 动态组筛选，不能提前丢掉全错组。GRPO 的 clipping、loss 聚合仍须明确配置；reference KL 已确定关闭，不是只更改算法名称。教师门控改变了蒸馏目标：这是选择性 OPD，不等同于全轨迹无条件 OPD。失败轨迹上的负 GRPO 优势与 OPD 指导同时存在；不能只取成功轨迹重新计算组优势。

已确认每题 rollout 数：smoke 使用 2 条，正式小规模实验从 4 条起步；后续根据真实显存峰值和吞吐，单变量尝试 5 条或更多。每条仍最多搜索 2 次。同组轨迹允许分批生成，但必须来自同一学生策略版本，完成该批采样和评分前不更新学生。增加 group size 不等于提高并发数，不预先承诺能够容纳或改善效果；全错时不额外重采样凑正确答案。

2026-09-20 用户批准：首版关闭冻结初始学生的 reference KL，包括纯 GRPO 对照与 GRPO + 失败 OPD 分支；保留 rollout old-policy logprob、概率比与 clipping。教师 OPD 的分布指导仍存在，不随 reference KL 一同关闭。DAPO 保留为后续可研究备选，不自动替换当前方案；若教师指导效果不佳，先用 OPD 系数为零的同算法对照定位原因。未来采用 DAPO 时仍须保留全错组供 OPD 使用，不能重新引入提前丢弃失败组的路径。

建议保留如下实验矩阵，运行顺序与预算尚待细化：

| 冷启动 | 直接评测 | + RL | + RL 与失败 OPD |
|---|---|---|---|
| A：CE-only | A0 | A1 | A2 |
| B：CE + Top-k | B0 | B1 | B2 |

已确认：冷启动不以教师答案是否通过 verifier 作为筛选条件，仅排除无合法最终答案的轨迹。RL 阶段不增加教师独立作答或答对资格检查；教师仅对学生实际轨迹提供概率监督。学生答错的有效轨迹保留用于 GRPO 与失败 OPD，学生答对则关闭 OPD。检索服务故障等环境异常单独处理，不直接记为学生答错。教师概率并不保证医学正确性，仍需监测其指导效果。

OPD 教师只读取被评分 token 之前的实际上下文；不输入未来答案或 gold。历史失败轨迹可以用于接口诊断，不能冒充当前学生的 on-policy 数据。

## 8. 工程方向与待验证项

### 已确认的精度、smoke 与 checkpoint 策略

2026-09-20 用户批准 Search-R1 7B 教师使用 BF16，适用于冷启动生成/评分和 RL 失败轨迹 OPD 评分。先按阶段调度，不预先增加教师量化方案；后续真实出现 OOM 再定位并讨论调整。

先运行完整链路 smoke，检查运行失败、OOM、数值异常以及实际更新；smoke 通过不代表能力提升。学生每题 2 条 rollout、每条最多 2 次搜索，长度按已确认的 4096 + 500 口径。

保留中间、最佳与最后 checkpoint，并保留对应配置、代码版本和评测结果；最佳 checkpoint 的选择指标及频率还需明确，只能依据开发集，不使用最终测试集选择。用户尚未批准正式冷启动 epoch 数、正式 RL 更新步数或具体评测频率；此前建议的 3 epochs、50 steps、step 0/25/50 仅为讨论候选，不能自动写入已确定训练预算。正式预算在 smoke 后结合实际吞吐和学习表现决定。

### 教师指导强度：小系数起步

用户偏好：在线教师指导初期不要太强。DGPO 表 8 的 RL 教师 KL 系数 beta=0.001；冷启动 KD 系数 lambda=1.0，二者不可混用。原方法把教师 KL 放入奖励再经 PPO/GAE，本项目的独立 GRPO + OPD 损失不保证数值等价。

当前建议在线 OPD 系数 `opd_coef=0.001` 作为 smoke/pilot 起点，`0` 作为关闭指导的对照；尚不是已验证有效的正式超参数。先固定系数，不引入动态调权。建议每条轨迹按有效模型生成 token 求平均，再对完整原 batch 的轨迹求平均，成功轨迹 OPD 项置零；不只按失败子集重新平均，避免失败比例降低后对剩余失败样本隐式放大权重。此归一化方案待后续确认并与框架实际实现核对。

同时记录未加权/加权 OPD 项、教师学生 logprob 差、失败比例、熵和 dev 指标，并在小规模诊断中检查独立梯度贡献。不能只凭loss绝对值判断指导强度；全错组仍应验证非零有效教师梯度，系数过小也可能几乎不产生学习。

以下是工程建议，尚未通过单卡实测：

- 冷启动先离线生成教师轨迹和 Top-k 缓存，再卸载教师训练学生。
- 在线采用“学生 rollout → verifier 判定 → 教师评分 → 学生更新”的阶段式资源调度，避免假定多模型可同时驻留。
- 保留现有 veRL/AgentLoop，优先复用已经存在的蒸馏接口；不先升级全部依赖。
- 冷启动可尝试 QLoRA；RL actor 是否支持所需低比特路径须独立核实，不能外推 SFT 结果。
- sampled-token 分数减少缓存与传输，但不免除教师前向计算，也不保证低峰值显存。

源码初查：本地 `MedSearch/.deps/verl` HEAD 为 `23af6a7a2e8d6efeeb2adbe5d1689c7a24f503a3`，包含教师管理和蒸馏损失入口。此为源码存在性检查，不代表完整管线兼容或已运行。

## 9. 后续优先讨论的问题

1. **GRPO 与失败 OPD 的实现口径。** 分流规则已确定；实施时关闭旧 DAPO 动态筛组并验证全错组可以产生 OPD 更新，明确两个损失的独立归一化与权重。
2. **教师指导诊断。** 已决定不增加独立教师资格检查；监测学生走偏后的教师信号、梯度和独立评测表现。
3. **软分布冷启动接入。** K=32、T=1、alpha=0.1 已确定，损失沿用 veRL；候选教师 tokenizer 映射已核对，后续验证共同输出支持集、有效生成位置和公平预算。
4. **训练稳定性。** DGPO 的 PPO 结论不能直接外推到我们的 GRPO + OPD；记录奖励方差、熵、KL、截断、梯度和 dev 行为变化。由 DAPO 改 GRPO 是实验设计调整，不代表已证明稳定性或效果更优。
5. **训练目标接入。** 单独 RL/OPD loss 与合并 advantage 在 clipping 下不默认等价，需确定一个可验证定义。
6. **判定器一致性。** 固定模型版本、输入模板与阈值；检查误判，训练 verifier 分数不作为唯一最终效果证据。
7. **单卡可行性。** 教师评分、缓存、卸载、学生训练的显存及主机内存峰值、延迟和失败恢复。
